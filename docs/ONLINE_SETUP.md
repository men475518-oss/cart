# オンライン対戦サーバーの立てかた

もふもふカートのオンライン対戦には、プレイヤー同士の位置やアイテムを中継する **WebSocket サーバー**が必要です。
GitHub Pages はファイルを配るだけの静的配信なので、そこにサーバーを置くことはできません。中継サーバーだけを別の場所に用意します。

このリポジトリには 2 種類の中継サーバーが入っていて、どちらも**通信プロトコルは同じ**です。どちらを使ってもゲーム側の設定は「サーバーの URL を入れるだけ」です。

| 実装 | ファイル | 向いている用途 |
| --- | --- | --- |
| Cloudflare Workers 版 | `worker/index.js` | インターネット越しに、いつでも遊べるようにする（無料） |
| Node 版 | `server/index.js` | 手元の PC で動かす。同じ Wi-Fi 内での対戦や開発 |

---

## 方法 A: Cloudflare Workers で常時公開する（おすすめ）

Cloudflare の無料プランは WebSocket に対応していて、月およそ 300 万リクエストまで無料です。
このゲームは 1 レースあたり数百リクエスト程度なので、まず使い切りません。

### 手順

```bash
# 1. Cloudflare にログインする（ブラウザが開きます。初回だけ）
npx wrangler login

# 2. 公開する
npm run worker:deploy
```

2 つ目のコマンドが、次のような URL を表示します。

```
https://mofukart-server.<あなたのサブドメイン>.workers.dev
```

この URL をコピーして、ゲームの **オンライン対戦 → サーバー設定** の欄に貼り付けてください。
`https://` のまま入れれば、ゲーム側が自動で `wss://` に変換して接続します。一緒に遊ぶ人にも同じ URL を伝えれば、全員が同じ部屋に入れます。

### 動いているか確かめる

ブラウザで `https://<あなたの URL>/health` を開くと、次のような応答が返ります。

```json
{ "ok": true, "rooms": 0, "clients": 0, "queue": 0 }
```

### 手元で試す

デプロイ前に、Cloudflare の実行環境をそのまま手元で動かして確認できます。

```bash
npm run worker:dev     # ws://127.0.0.1:8788 で起動
npm run worker:test    # 別のターミナルで、通信プロトコルを一通り検証する
```

`npm run worker:test` は部屋の作成・参加・準備完了・レース開始・走行データの中継・なりすまし防止・ゴール判定・観戦・ホスト交代・カジュアルマッチまでを自動で確認します。

### しくみ

- Worker は 1 つの **Durable Object**（`RaceHub`）に、すべての部屋・待機列・WebSocket 接続を持たせています。部屋コードでの合流やカジュアルマッチの待ち合わせを、単純な形で実装できるためです。
- **ハイバネーション API** を使っているので、誰も遊んでいない間は実行時間を消費しません。復帰したときは Durable Object のストレージから部屋の状態を復元します。
- 結果確定の締め切りやカジュアルマッチの待ち時間は、`setTimeout` ではなく **アラーム**で管理しています。ハイバネーション中でも時間が来れば起きるためです。
- 走行データ（毎秒 15 回）は保存せず中継だけします。保存するのは部屋の構成が変わったときだけです。

### 規模について

すべての部屋を 1 つの Durable Object が処理します。友達同士で遊ぶ規模なら十分ですが、同時に多くの部屋を捌きたい場合は、部屋ごとに Durable Object を分け、待ち行列専用のオブジェクトを別に置く形へ拡張してください。

## 方法 B: 手元の PC を一時的に公開する（アカウント不要）

その場かぎりで友達と遊ぶだけなら、自分の PC でサーバーを動かし、トンネルで一時的な URL を発行するのが手軽です。

```bash
npm start                                        # 中継サーバーを起動（ポート 8787）
cloudflared tunnel --url http://localhost:8787   # 別のターミナルで実行
```

表示された `https://<ランダムな名前>.trycloudflare.com` を、ゲームのサーバー設定に貼り付けます。
PC を閉じるとアドレスは失効するので、遊ぶたびに発行し直す使い方です。

---

## 方法 C: 同じ Wi-Fi の中だけで遊ぶ

インターネットを使わず、同じ Wi-Fi につながった端末同士で遊べます。

```bash
npm run dev      # ゲーム本体（http://<この PC の IP>:5173）
npm run server   # 中継サーバー（ポート 8787）
```

他の端末のブラウザで `http://<この PC の IP>:5173` を開き、サーバー設定に `<この PC の IP>:8787` を入れてください。

> **注意**: この方法では、ゲームを **GitHub Pages ではなく `npm run dev` から開く**必要があります。
> GitHub Pages は HTTPS で配信されるため、ブラウザの仕様上、暗号化されていない `ws://192.168.x.x` への接続はブロックされます。

## うまくつながらないとき

| 症状 | 原因と対処 |
| --- | --- |
| 「対戦サーバーのアドレスを入力してください」と出る | GitHub Pages などの静的ホスティングで開いています。上のいずれかの方法でサーバーを用意し、URL を入力してください |
| 「サーバーに接続できません」と出る | URL の打ち間違い、またはサーバーが起動していません。`/health` を開いて応答を確認してください |
| GitHub Pages から LAN のサーバーにつながらない | HTTPS のページからは `wss://` にしか接続できません。方法 A か B を使うか、方法 C のようにゲーム自体をローカルから開いてください |
| 部屋に入れず「レース中です」と出る | すでにレースが始まっています。観戦ボタンから参加できます |
